## 재시도 로직 상세 (Retry Logic Details)

```
시도 횟수     대기 시간
─────────────────────
   1         → 실패 → 10초 대기
   2         → 실패 → 20초 대기
   3         → 실패 → 30초 대기
   4         → 실패 → 40초 대기
   5         → 실패 → 50초 대기
  ...
  30         → 실패 → 300초 대기
  31+        → 실패 → 300초 대기 (최대값 고정)
  ...
 99,999      → 실패 → 종료
```

**대기 시간 계산 공식**:
```python
wait_time = min(10 * attempt_number, 300)
```

## 실행 모드 비교 (Execution Mode Comparison)

| 특성 | Job 1: Local | Job 2: Remote |
|------|-------------|---------------|
| 실행 환경 | GitHub Actions Runner | 사용자 서버 |
| 트리거 | Push to main / Manual | Manual만 |
| 조건 | 항상 실행 | 실제 서버 IP 입력 시 |
| 타임아웃 | 8시간 | 60분 |
| 인증 | 불필요 | SSH Password/Key |
| 최대 재시도 | 99,999 | 99,999 |
| 로그 저장 | Artifacts | SSH 출력 |

```
    │
    ├─ 타임아웃 ──────────────→ 로그 기록 → 재시도
    │
    ├─ 네트워크 오류 ─────────→ 로그 기록 → 재시도
    │
    ├─ 패키지 오류 ───────────→ 로그 기록 → 재시도
    │
    └─ 최대 재시도 도달 ──────→ 로그 기록 → 실패 종료
```

## 사용 사례 (Use Cases)

### Case 1: 개발 환경 자동 설정
```yaml
트리거: Push to main
실행: Job 1만 (로컬)
목적: CI/CD 파이프라인의 일부로 네트워크 도구 검증
```

### Case 2: 프로덕션 서버 초기 설정
```yaml
트리거: Manual Dispatch
입력: server_host=203.0.113.1
실행: Job 1 + Job 2
목적: 새 서버에 네트워크 환경 구성
인증: SSH_PRIVATE_KEY
```

### Case 3: 장애 복구
```yaml
트리거: Manual Dispatch
입력: max_retries=10000
실행: Job 2 (원격)
목적: 네트워크 문제로 실패한 서버 재설정
재시도: 성공할 때까지 반복
```
